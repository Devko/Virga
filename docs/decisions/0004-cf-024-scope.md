# 0004: Scope of CF-024

- Status: accepted; revisit after S-05
- Date: 2026-10-30
- Relates to: D-11 (phase 1 rules), D-14 (token profiles), S-05 (permission groups)
- Source: round 4, `fix-lifecycle` (CF-024 version 2); R2-09 of the [round 2 review](../reviews/2026-10-30-security-review.md)

## Context

CF-024 reports plain-text variables whose value looks like a secret. Version 1 read Worker versions only (`worker_version.plain_text_vars`). The pages collector stores the same verdicts for Pages env vars (`pages_project.plain_text_vars`), and round 4 extended the rule to them.

Two shapes were possible:

| Option | `requires` | Without complete `pages` coverage |
| --- | --- | --- |
| One rule for Workers and Pages | CF-024: `[workers, pages]` | CF-024 is `not_evaluated`; Worker findings freeze |
| A separate rule ID for Pages | CF-024: `[workers]`; new ID: `[pages]` | Only the Pages rule is `not_evaluated`; Worker evaluation stays independent |

## Decision

- CF-024 is one rule for Workers and Pages (version 2) and requires `workers` and `pages`.
- The rule answers one question for the account: is a secret kept in plain text? A run that could not read one of the two classes is `not_evaluated` as a whole, not `evaluated` with half of the variables unread.
- Findings stay apart per subject: one per Worker (`CF-024:worker_script:<name>`) and one per Pages project (`CF-024:pages_project:<name>`). A change on one side never opens or resolves a finding on the other. Worker fingerprints, subjects and evidence are the same as in version 1, so existing findings carry over.
- A value the collector could not inspect (`looks_secret` `null`) is unknown, not clean. A subject with such a variable and none that looks like a secret gets an undecided row.

## Consequences

- **A missing `pages` class freezes Worker findings.** When `pages` is not `complete` (for example `no_permission`), CF-024 is `not_evaluated` with `pages` in `missing`. No Worker finding opens or resolves, although `workers` is complete. The scan summary shows this per rule (`ruleRuns`).
- The `pages` class needs Pages Metadata Read, which S-05 still has to confirm (operator guide, inventory profile). Pages Read works too, with a write check warning, because it also reads content.
- If the role reads the project but not the values of plain-text env vars, CF-024 returns undecided rows for every project with plain-text vars. Worker findings are not affected.
- The operator guide lists `workers, pages` for CF-024. `packages/rules/test/evaluate.cf024.test.ts` covers the coupling: without complete `pages` coverage the rule is not evaluated and changes no Worker finding.

## Revisit after S-05

S-05 shows whether an inventory token with Pages Metadata Read can read `GET /accounts/{id}/pages/projects/{name}`, and whether the response holds the values of plain-text env vars.

- Both work: keep one rule.
- Otherwise: move Pages to its own rule ID with `requires: [pages]`, and return CF-024 to `requires: [workers]`. Pages findings then get new fingerprints under the new ID (data-model: a change of meaning gets a new rule ID).
